Elegí un término de la lista para ver su definición, características y ejemplos de uso.

Ágil

Enfoque de desarrollo de software que organiza el trabajo en ciclos cortos, entrega versiones funcionales del producto con frecuencia y se adapta a los cambios.

Características principales
  • Iterativo e incremental.
  • Colaboración constante con el cliente.
  • Flexibilidad frente a los cambios.
  • Equipos autoorganizados y mejora continua.
Ejemplo de uso
  • Metodologías como Scrum, Kanban y XP.
  • Un equipo que entrega una mejora de la app cada 2 semanas.
  • Reuniones diarias cortas para coordinar el trabajo.
  • Una demo al cliente al final de cada ciclo para recibir su opinión.
API

Conjunto de reglas y funciones que permite que dos aplicaciones o sistemas se comuniquen e intercambien datos sin conocer cómo funciona cada uno por dentro.

Características principales
  • Actúa como intermediaria entre sistemas.
  • Define qué se puede pedir y cómo se recibe la respuesta.
  • Oculta la complejidad interna y es reutilizable.
  • Suele intercambiar datos en formatos como JSON.
Ejemplo de uso
  • Una app del clima que consulta los datos de un servicio meteorológico.
  • El botón “Iniciar sesión con Google”.
  • La pasarela de pago de una tienda online.
  • Mostrar un mapa de Google Maps dentro de una app o sitio web.
Backlog

Lista priorizada de tareas, requisitos, mejoras y errores pendientes de desarrollar en un proyecto.

Características principales
  • Está ordenada por prioridad.
  • Se actualiza durante todo el proyecto y es visible para todo el equipo.
  • Cada ítem describe el valor que aporta.
  • En Scrum se divide en Product Backlog y Sprint Backlog.
Ejemplo de uso
  • Una historia de usuario: “Como usuario, quiero recuperar mi contraseña”.
  • Un tablero de Jira o Trello con las tareas pendientes.
  • El Product Owner reordena el backlog antes de planificar el Sprint.
  • Agregar al backlog un error reportado por un usuario para corregirlo más adelante.
Bug

Error o defecto en el software que hace que funcione de forma incorrecta o inesperada.

Características principales
  • Puede originarse en el código, el diseño o requisitos mal entendidos.
  • Tiene distinta gravedad: desde un detalle visual hasta una falla crítica.
  • Se detecta durante las pruebas o lo reportan los usuarios.
  • Se registra, se prioriza y se corrige; un buen reporte incluye los pasos para reproducirlo.
Ejemplo de uso
  • Un botón “Enviar” que no responde.
  • Un carrito de compras que calcula mal el total.
  • Una app que se cierra sola al abrir cierta pantalla.
  • Reportar el error en herramientas como Jira o Bugzilla.
Calidad

Grado en que un producto o servicio cumple los requisitos y satisface las necesidades y expectativas del usuario.

Características principales
  • Se evalúa con atributos como funcionalidad, fiabilidad, usabilidad, eficiencia, mantenibilidad y portabilidad.
  • Está presente en todo el proceso, no solo al final.
  • Prioriza prevenir los errores antes que corregirlos.
  • Busca la mejora continua y se verifica con pruebas y métricas.
Ejemplo de uso
  • Ejecutar pruebas unitarias y de integración antes de lanzar.
  • Hacer revisiones de código entre compañeros.
  • Evaluar el producto con las normas ISO/IEC 9126 o 25000.
  • Analizar el código con herramientas como SonarQube.
Código fuente

Conjunto de instrucciones escritas por programadores en un lenguaje de programación, que luego se convierte en un programa ejecutable.

Características principales
  • Es legible para las personas y debe ser claro y fácil de mantener.
  • Se escribe en un lenguaje de programación (Python, Java, JavaScript, etc.).
  • Se organiza en archivos, funciones y clases.
  • Se guarda con control de versiones, por ejemplo Git.
Ejemplo de uso
  • Los archivos .html, .css y .js de esta página web.
  • Un repositorio de GitHub con el proyecto.
  • Revisar los cambios de un compañero antes de incorporarlos.
  • Proyectos de código abierto, donde cualquiera puede ver y mejorar el código.
DevOps

Cultura y conjunto de prácticas que unen a los equipos de desarrollo (Dev) y de operaciones (Ops) para entregar software de forma rápida, frecuente y confiable.

Características principales
  • Une desarrollo y operaciones en un mismo flujo de trabajo.
  • Automatiza la integración, las pruebas y el despliegue.
  • Promueve la colaboración y la responsabilidad compartida.
  • Monitorea el sistema de forma continua para mejorarlo.
Ejemplo de uso
  • Un pipeline que compila, prueba y publica la app automáticamente.
  • Un equipo que despliega varias veces por semana con poco riesgo.
  • Alertas automáticas que avisan cuando un servicio falla.
  • Infraestructura definida en archivos de configuración, como YAML.
Entrega continua

Práctica que mantiene el software siempre listo para publicarse, de modo que los cambios puedan entregarse a los usuarios de manera frecuente, rápida y segura.

Características principales
  • Mantiene el producto siempre en condiciones de ser publicado.
  • Se apoya en pruebas automáticas en cada cambio.
  • Reduce el riesgo al entregar cambios pequeños y frecuentes.
  • Suele formar parte de un pipeline de CI/CD.
Ejemplo de uso
  • Publicar una mejora de la web el mismo día en que se termina.
  • Un pipeline que deja cada versión lista para desplegar con un clic.
  • Entregar cambios pequeños a los usuarios todas las semanas.
  • Volver rápido a la versión anterior si algo sale mal.
Funcionalidad

Capacidad del software para realizar, de forma correcta y completa, las funciones para las que fue diseñado según las necesidades del usuario. Es una de las características de calidad de la norma ISO/IEC 9126.

Características principales
  • Se refiere a lo que el software hace, no a cómo lo hace.
  • Incluye adecuación, exactitud, interoperabilidad y seguridad.
  • Se verifica con pruebas funcionales.
  • Es una de las 6 características de calidad de ISO/IEC 9126.
Ejemplo de uso
  • Que un carrito de compras sume bien los productos y el total.
  • Que el inicio de sesión solo deje entrar con usuario y contraseña correctos.
  • Que un reporte exporte los datos pedidos en PDF.
  • Probar cada función de la app contra sus requisitos.
Git

Sistema de control de versiones distribuido que registra los cambios del código a lo largo del tiempo y permite que varias personas colaboren en el mismo proyecto.

Características principales
  • Guarda el historial completo de cambios del código.
  • Permite trabajar en ramas (branches) sin afectar la versión principal.
  • Es distribuido: cada persona tiene una copia completa del repositorio.
  • Facilita unir (merge) el trabajo de varias personas.
Ejemplo de uso
  • Guardar cambios con commit y subirlos al repositorio con push.
  • Un repositorio de GitHub compartido por todo el equipo.
  • Crear una rama para probar una función nueva sin romper el proyecto.
  • Volver a una versión anterior del código si algo falla.
Historia de usuario

Descripción breve y simple de una necesidad del usuario, escrita desde su perspectiva, que representa una funcionalidad con valor para el negocio.

Características principales
  • Se escribe en lenguaje simple, desde el punto de vista del usuario.
  • Suele seguir el formato “Como [usuario], quiero [acción] para [beneficio]”.
  • Es corta y se completa con criterios de aceptación.
  • Se ordena y prioriza dentro del backlog.
Ejemplo de uso
  • “Como cliente, quiero recuperar mi contraseña para volver a entrar.”
  • “Como alumno, quiero ver mis notas para saber cómo voy.”
  • Una tarjeta en Trello o Jira con su criterio de aceptación.
  • Elegir y estimar historias al planificar un Sprint.
Iteración

Período corto y de duración fija en el que el equipo planifica, desarrolla, prueba y entrega un incremento del producto, para luego revisar lo hecho y mejorar.

Características principales
  • Tiene una duración fija y corta, por ejemplo de 1 a 4 semanas.
  • Termina con una parte del producto funcionando.
  • Se repite en ciclos, incorporando lo aprendido.
  • Permite adaptarse a los cambios entre una iteración y la siguiente.
Ejemplo de uso
  • Un Sprint de 2 semanas en Scrum.
  • Entregar una funcionalidad nueva al cliente en cada iteración.
  • Revisar al final de cada iteración qué salió bien y qué mejorar.
  • Modelo iterativo: construir una versión básica y mejorarla en cada vuelta.
Jira

Herramienta de gestión de proyectos y seguimiento de tareas y errores, usada especialmente por equipos que trabajan con metodologías ágiles.

Características principales
  • Permite crear y seguir tareas, historias de usuario y errores.
  • Ofrece tableros Scrum y Kanban.
  • Muestra el avance con reportes y gráficos.
  • Se puede integrar con otras herramientas, como las de control de versiones.
Ejemplo de uso
  • Un tablero con las columnas Por hacer, En curso y Hecho.
  • Registrar un error con los pasos para reproducirlo.
  • Planificar el backlog y los Sprints de un proyecto.
  • Ver el gráfico de avance (burndown chart) del Sprint.
Kanban

Método ágil de gestión visual del trabajo que representa las tareas en un tablero y limita el trabajo en curso (WIP) para mejorar el flujo y la entrega continua de valor.

Características principales
  • Visualiza el trabajo en un tablero con columnas.
  • Limita la cantidad de tareas en progreso (WIP).
  • Busca un flujo de trabajo continuo, sin iteraciones fijas.
  • Mejora de forma continua a partir de las métricas del flujo.
Ejemplo de uso
  • Un tablero con Por hacer, En proceso y Hecho.
  • Un equipo de soporte que atiende los pedidos a medida que llegan.
  • Limitar “En proceso” a 2 tareas para evitar la sobrecarga.
  • Medir cuánto tarda una tarea desde que empieza hasta que termina.
Límite WIP

Cantidad máxima de tareas que pueden estar en progreso al mismo tiempo en una columna o estado del tablero, para evitar la sobrecarga del equipo.

Características principales
  • Se define para cada columna del tablero.
  • Evita empezar muchas tareas sin terminar ninguna.
  • Ayuda a detectar cuellos de botella.
  • Obliga a terminar algo antes de comenzar otra tarea.
Ejemplo de uso
  • “En proceso” permite como máximo 2 tareas.
  • No se puede mover una tercera tarea hasta terminar una.
  • Un equipo ve la columna “Pruebas” llena y ayuda a terminar antes de seguir.
  • Practicarlo en el tablero Kanban interactivo de la sección Metodologías en detalle.
Mantenimiento

Conjunto de actividades que se realizan después de la entrega del software para corregir errores, mejorarlo o adaptarlo a nuevos entornos o necesidades.

Características principales
  • Puede ser correctivo, adaptativo, perfectivo o preventivo.
  • Comienza cuando el software ya está en uso.
  • Suele ser una de las etapas más largas del ciclo de vida.
  • Se facilita con código claro, pruebas y buena documentación.
Ejemplo de uso
  • Corregir un error que reportaron los usuarios (correctivo).
  • Adaptar la app a una nueva versión del sistema operativo (adaptativo).
  • Agregar una mejora pedida por el cliente (perfectivo).
  • Reorganizar el código para evitar problemas futuros (preventivo).
No funcional

Requisito que describe cómo debe comportarse el sistema, es decir, sus cualidades (rendimiento, seguridad, usabilidad, etc.), y no qué funciones realiza.

Características principales
  • Describe cualidades del sistema, no funciones concretas.
  • Se puede medir, por ejemplo con el tiempo de respuesta.
  • Afecta a todo el sistema y no a una sola función.
  • Es clave para la calidad que percibe el usuario.
Ejemplo de uso
  • “La página debe cargar en menos de 3 segundos.”
  • “Los datos de los usuarios deben guardarse cifrados.”
  • “El sistema debe funcionar en celular y en computadora.”
  • “La app debe estar disponible el 99 % del tiempo.”
Objetivo de calidad

Meta concreta y medible relacionada con la mejora de la calidad del producto o del proceso de desarrollo.

Características principales
  • Es específico y medible.
  • Se define al inicio y se revisa durante el proyecto.
  • Puede referirse al producto (fallas) o al proceso (tiempos).
  • Guía las pruebas y las mejoras del equipo.
Ejemplo de uso
  • “Reducir a menos de 5 los errores críticos por versión.”
  • “Lograr que el 80 % del código tenga pruebas automáticas.”
  • “Corregir los errores en menos de 48 horas.”
  • “Mantener un puntaje alto de usabilidad en las encuestas.”
Prueba (Testing)

Actividad que consiste en ejecutar el software para verificar que funcione correctamente, cumpla con los requisitos y detectar errores antes de entregarlo.

Características principales
  • Busca encontrar errores y confirmar que se cumplen los requisitos.
  • Puede ser manual o automatizada.
  • Tiene niveles: unitarias, de integración, de sistema y de aceptación.
  • Se hace durante todo el desarrollo, no solo al final.
Ejemplo de uso
  • Una prueba unitaria que comprueba una función de cálculo.
  • Probar que el formulario de contacto envía los datos.
  • Pruebas de aceptación con el cliente antes de entregar.
  • Automatizar pruebas con herramientas como Selenium.
QA

Aseguramiento de la calidad (Quality Assurance): conjunto de procesos y prácticas planificadas que buscan prevenir errores y garantizar la calidad del software durante todo su desarrollo.

Características principales
  • Se centra en prevenir los errores, no solo en encontrarlos.
  • Abarca todo el proceso de desarrollo.
  • Define estándares, revisiones y pruebas.
  • Es responsabilidad de todo el equipo, no de una sola persona.
Ejemplo de uso
  • Definir una lista de control de calidad para cada entrega.
  • Hacer revisiones de código entre compañeros.
  • Aplicar normas como ISO/IEC 9126 o ISO 25000.
  • Analizar el código con herramientas como SonarQube.
Requisito

Condición o necesidad que el software debe cumplir para satisfacer a los usuarios; puede ser funcional (qué hace) o no funcional (cómo se comporta).

Características principales
  • Describe una necesidad del usuario o del negocio.
  • Se clasifica en funcional y no funcional.
  • Debe ser claro, medible y verificable.
  • Se documenta y puede ajustarse durante el proyecto.
Ejemplo de uso
  • Funcional: “El usuario puede registrarse con su correo.”
  • No funcional: “El sistema responde en menos de 2 segundos.”
  • Un documento de requisitos de software (SRS).
  • Historias de usuario ordenadas en un backlog.
Scrum

Metodología ágil que organiza el trabajo en ciclos cortos llamados Sprints, con roles, eventos y artefactos definidos, para entregar valor de forma frecuente.

Características principales
  • Trabaja en Sprints de 1 a 4 semanas.
  • Tiene 3 roles: Product Owner, Scrum Master y equipo de desarrollo.
  • Incluye eventos como la planificación, la reunión diaria, la revisión y la retrospectiva.
  • Usa 3 artefactos: Lista de Producto, Lista del Sprint e Incremento.
Ejemplo de uso
  • Un equipo que entrega una versión de la app cada 2 semanas.
  • Una reunión diaria de 15 minutos para coordinar el trabajo.
  • Mostrar el avance al cliente en la revisión del Sprint.
  • Mejorar la forma de trabajar en la retrospectiva.
TDD

Desarrollo guiado por pruebas (Test-Driven Development): enfoque en el que primero se escribe la prueba, luego el código necesario para que pase y, por último, se mejora ese código.

Características principales
  • Sigue el ciclo rojo, verde y refactorizar.
  • Las pruebas se escriben antes que el código.
  • Genera código simple y con pruebas desde el inicio.
  • Es una práctica central de Extreme Programming (XP).
Ejemplo de uso
  • Escribir una prueba que falle para una función que todavía no existe.
  • Programar lo mínimo necesario para que la prueba pase.
  • Mejorar el código y volver a correr las pruebas.
  • Usar herramientas como JUnit, pytest o Jest.
Usabilidad

Facilidad con la que un usuario puede aprender, usar y alcanzar sus objetivos con el software, de forma eficaz y satisfactoria.

Características principales
  • Se refiere a qué tan fácil de usar es el software.
  • Incluye facilidad de aprendizaje, claridad y satisfacción.
  • Se evalúa observando a usuarios reales.
  • Es una de las características de calidad de ISO/IEC 9126.
Ejemplo de uso
  • Un menú claro, con botones fáciles de encontrar.
  • Mensajes de error que explican cómo solucionar el problema.
  • Una prueba con usuarios para ver dónde se traban.
  • Una web que se adapta bien al celular.
Versión

Estado específico del software en un momento determinado, identificado por un número o nombre, que refleja los cambios, mejoras o correcciones realizados.

Características principales
  • Se identifica con un número, por ejemplo 2.1.0.
  • Cada versión agrupa un conjunto de cambios.
  • Permite volver atrás si una versión falla.
  • Se administra con herramientas de control de versiones, como Git.
Ejemplo de uso
  • Pasar de la versión 1.0 a la 1.1 por corregir errores.
  • Lanzar la versión 2.0 con funciones nuevas.
  • Etiquetar una versión en Git con un tag.
  • Mantener un registro de cambios (changelog) de cada versión.
WIP

Work In Progress (trabajo en progreso): tareas que ya se empezaron y todavía no se terminaron.

Características principales
  • Cuenta las tareas que se están realizando en un momento dado.
  • Se visualiza en la columna “En proceso” del tablero.
  • Demasiado WIP hace más lento el trabajo.
  • Se controla con un límite WIP.
Ejemplo de uso
  • Tres tareas en la columna “En proceso” de un tablero.
  • Un equipo que termina lo empezado antes de tomar tareas nuevas.
  • Medir cuántas tareas hay en progreso cada semana.
  • Reducir el WIP para entregar más rápido.
XP

Extreme Programming: metodología ágil que promueve la calidad del código, la colaboración con el cliente y las entregas frecuentes mediante prácticas técnicas.

Características principales
  • Se basa en valores como comunicación, simplicidad, feedback, coraje y respeto.
  • Usa prácticas técnicas como la programación en parejas y TDD.
  • Integra el código y entrega en ciclos muy cortos.
  • El cliente forma parte del equipo.
Ejemplo de uso
  • Dos programadores trabajando juntos en la misma computadora.
  • Escribir primero las pruebas con TDD.
  • Integrar el código varias veces por día.
  • Refactorizar el código para mantenerlo simple.
YAML

Formato de archivo de texto simple y legible por las personas, utilizado para escribir configuraciones y definir datos, por ejemplo en pipelines de CI/CD.

Características principales
  • Es fácil de leer y de escribir.
  • Usa sangrías (espacios) para organizar la información.
  • Se guarda en archivos con extensión .yml o .yaml.
  • Es muy usado en archivos de configuración.
Ejemplo de uso
  • Un archivo de GitHub Actions para ejecutar pruebas automáticas.
  • La configuración de un pipeline de CI/CD.
  • Un archivo docker-compose.yml.
  • Definir los ajustes de una aplicación.
Zero Defect

Enfoque de calidad que busca minimizar o eliminar los errores en el desarrollo del software, haciendo las cosas bien desde la primera vez.

Características principales
  • Se basa en prevenir los errores desde el inicio.
  • Propone hacer las cosas bien desde la primera vez.
  • Promueve revisiones y pruebas constantes.
  • Busca el mejor resultado posible, aunque en la práctica no siempre se logra.
Ejemplo de uso
  • Revisar el código antes de incorporarlo al proyecto.
  • Automatizar pruebas para detectar fallas desde el principio.
  • Corregir un error en su causa y no solo en el síntoma.
  • Fijar como meta cero errores críticos en cada entrega.
