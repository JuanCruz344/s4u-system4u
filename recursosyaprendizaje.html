Ágil

Enfoque de desarrollo de software que organiza el trabajo en ciclos cortos, entrega versiones funcionales del producto con frecuencia y se adapta a los cambios.

Características principales
  • Iterativo e incremental.
  • Colaboración constante con el cliente.
  • Flexibilidad frente a los cambios.
  • Equipos autoorganizados y mejora continua.
Ejemplo de uso
  • Metodologías como Scrum, Kanban y XP.
  • Un equipo que entrega una mejora de la app cada 2 semanas.
  • Reuniones diarias cortas para coordinar el trabajo.
  • Una demo al cliente al final de cada ciclo para recibir su opinión.
API

Conjunto de reglas y funciones que permite que dos aplicaciones o sistemas se comuniquen e intercambien datos sin conocer cómo funciona cada uno por dentro.

Características principales
  • Actúa como intermediaria entre sistemas.
  • Define qué se puede pedir y cómo se recibe la respuesta.
  • Oculta la complejidad interna y es reutilizable.
  • Suele intercambiar datos en formatos como JSON.
Ejemplo de uso
  • Una app del clima que consulta los datos de un servicio meteorológico.
  • El botón “Iniciar sesión con Google”.
  • La pasarela de pago de una tienda online.
  • Mostrar un mapa de Google Maps dentro de una app o sitio web.
Backlog

Lista priorizada de tareas, requisitos, mejoras y errores pendientes de desarrollar en un proyecto.

Características principales
  • Está ordenada por prioridad.
  • Se actualiza durante todo el proyecto y es visible para todo el equipo.
  • Cada ítem describe el valor que aporta.
  • En Scrum se divide en Product Backlog y Sprint Backlog.
Ejemplo de uso
  • Una historia de usuario: “Como usuario, quiero recuperar mi contraseña”.
  • Un tablero de Jira o Trello con las tareas pendientes.
  • El Product Owner reordena el backlog antes de planificar el Sprint.
  • Agregar al backlog un error reportado por un usuario para corregirlo más adelante.
Bug

Error o defecto en el software que hace que funcione de forma incorrecta o inesperada.

Características principales
  • Puede originarse en el código, el diseño o requisitos mal entendidos.
  • Tiene distinta gravedad: desde un detalle visual hasta una falla crítica.
  • Se detecta durante las pruebas o lo reportan los usuarios.
  • Se registra, se prioriza y se corrige; un buen reporte incluye los pasos para reproducirlo.
Ejemplo de uso
  • Un botón “Enviar” que no responde.
  • Un carrito de compras que calcula mal el total.
  • Una app que se cierra sola al abrir cierta pantalla.
  • Reportar el error en herramientas como Jira o Bugzilla.
Calidad

Grado en que un producto o servicio cumple los requisitos y satisface las necesidades y expectativas del usuario.

Características principales
  • Se evalúa con atributos como funcionalidad, fiabilidad, usabilidad, eficiencia, mantenibilidad y portabilidad.
  • Está presente en todo el proceso, no solo al final.
  • Prioriza prevenir los errores antes que corregirlos.
  • Busca la mejora continua y se verifica con pruebas y métricas.
Ejemplo de uso
  • Ejecutar pruebas unitarias y de integración antes de lanzar.
  • Hacer revisiones de código entre compañeros.
  • Evaluar el producto con las normas ISO/IEC 9126 o 25000.
  • Analizar el código con herramientas como SonarQube.
Código fuente

Conjunto de instrucciones escritas por programadores en un lenguaje de programación, que luego se convierte en un programa ejecutable.

Características principales
  • Es legible para las personas y debe ser claro y fácil de mantener.
  • Se escribe en un lenguaje de programación (Python, Java, JavaScript, etc.).
  • Se organiza en archivos, funciones y clases.
  • Se guarda con control de versiones, por ejemplo Git.
Ejemplo de uso
  • Los archivos .html, .css y .js de esta página web.
  • Un repositorio de GitHub con el proyecto.
  • Revisar los cambios de un compañero antes de incorporarlos.
  • Proyectos de código abierto, donde cualquiera puede ver y mejorar el código.
